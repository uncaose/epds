# Verification methods catalog

The list to choose checks from. `docs/policies/choose-checks-by-risk-and-oracle.md` says how: pick by risk of being wrong times cost, record each method left out with a one-line reason, and never drop a method whose "mandatory when" applies at the work's rigor level (below `high` it is reported as done or `Unverified` with the reason; the selection rule removes no execution requirement SKILL.md sets and adds none below `high` or a release gate). The intake decomposition table's verify-condition column (`templates/intake.md`) names methods from this list. This file holds only the metadata needed to choose; each method's rules live in its policy.

Oracle: **exact** = an exact expected value; **invariant** = a rule that holds for every input; **relation** = a known relation between outputs of related inputs; **none-human** = no automatic oracle, a person or an independent judge decides. Cost: **low** = minutes, existing tools; **med** = hours, a harness or extra tool; **high** = a day or more, special tooling or several parties.
