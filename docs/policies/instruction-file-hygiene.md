# Keep instruction files short, plain, and audited

Write each always-loaded instruction file in plain wording without stacked emphasis (capital letters, "never", "critical", exclamation marks), keep it to about 200 lines holding only what the agent cannot learn by reading the repo (pitfalls, rationale, conventions that differ from tool defaults), move task-specific text into on-demand skills, put a rule that must never bend in a hook or deny rule instead of prose, and audit the files periodically with the EPDS audit command (`/epds-audit`) or the tool's own audit for stale, missing, or contradicting references, applying an edit only after a person approves the proposal.

**Why**: Current models follow plainly worded instructions, and stacked emphasis mostly makes the agent over-apply the rule. Prose cannot enforce anything, so a rule that must hold belongs in structure (`docs/policies/make-repeated-mistakes-impossible.md`). A line that keeps getting lost is a sign the file is too long, not that it needs louder words. Files written for older models, pointing at files or commands that no longer exist, or contradicting each other quietly cost every run; the periodic audit finds them, and stored instructions are claims to re-verify (`docs/policies/reverify-stored-knowledge.md`). The audit proposes and changes nothing until approved (`docs/COMMANDS.md` § `/epds-audit`).
