# Spend usage in proportion to the work

Name the cheapest model tier that can pass its check for every delegated unit (the top tier is only for planning, integration and final judgement, and a unit with no tier stated runs on the cheap tier, never silently on the parent's tier); choose context boundaries separately from WBS boundaries: keep tightly coupled units in one loop when they need the same decisions and intermediate findings; use fresh contexts for independently completable work, independent review, or a demonstrated context problem; when crossing a context boundary, hand off the required inputs, decisions, scope and check evidence through files rather than copying a growing transcript, clearing between unrelated tasks and summarizing only at natural breaks; treat a long session as a smell: write a handoff and start fresh when its context passes a set size, and after two failed corrections re-examine the premise and restart with a rewritten prompt; send no polling loops or chatty traffic to idle sessions and batch messages; measure usage weekly by session, sub-agent and model tier from the tool's own usage report and re-plan any unit or pattern that dominates it; cap turns or spend on unattended runs and require human acceptance at the end; TRIVIAL work needs none of this ceremony.

**Why**: A measured week showed one session consuming almost all usage, most of it in delegated sub-agents that silently inherited the most expensive tier, each call re-reading hundreds of thousands of cached tokens that still count toward the limit. Use the cheapest tier that passes the relevant checks. Fresh contexts can reduce repeated input, but may add handoff and rediscovery cost; compare completed-task quality, total usage and latency before choosing a boundary. Avoid idle traffic, and a failed third correction in the same context costs more than a rewritten prompt. Handoff form is `docs/policies/lean-handoff.md`; units and their tier come from the WBS (`docs/policies/wbs-first-planning.md`, `templates/intake.md` § 2); repeated waste is closed as in `docs/policies/make-repeated-mistakes-impossible.md`; an independent fresh reviewer helps, re-delegating the same task to the same worker does not.
